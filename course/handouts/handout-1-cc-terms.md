# 講義一｜Claude Code 會講到的詞

這兩天你是**里歐烘焙坊（虛構的店）的 AI 專案負責人**：把店搬上雲端，請一位 AI 主管（Claude Code，下稱 CC）顧著五位 AI 工讀生。CC 工作時會說一些你沒聽過的詞。不用背。每個詞看兩欄：**你要懂到什麼程度**、**用店裡的話怎麼想**。

## 兩個心法（先看這個）

1. **看不懂就反問**：「用店裡管理的話解釋。」CC 會換一種說法。
2. **CC 問你的問題只有三種**：**要不要跑？要哪一個？這樣對嗎？** 不是這三種，就請它重問。

---

## 一、環境（瀏覽器裡的雲端工作區）

| 詞 | 懂到什麼程度 | 店裡的比喻 |
|---|---|---|
| 雲端工作區（Claude Code on the web） | 知道是瀏覽器裡一台暫時的雲端電腦，CC 在裡面幫你做事；關掉不保證留著，要靠存檔 | 租來的臨時辦公室 |
| repo（GitHub 上的資料夾） | 知道是你專案檔案的存放處，也是你的存檔；課程裡它**只存檔，不負責部署** | 店的檔案櫃 |
| 存檔（commit、push） | 知道說「存檔」，CC 就會把改動記進你的 repo；每個實作段做完都要做 | 蓋章歸檔 |
| 專案資料夾 | 知道課程資料夾（就是你的 repo）是工作的地方，所有檔案都在裡面 | 一間辦公室 |
| 環境變數 | 知道是放金鑰的地方，在環境設定裡，不寫進檔案、不貼進對話 | 保險箱，只有 CC 開得了 |
| 終端機 | 知道 CC 會在裡面打指令，**你不用碰** | 員工在後台操作機器 |
| Node | 知道它是讓程式跑起來的基本工具，`setup` 會幫你檢查 | 辦公室的水電 |
| CLAUDE.md | 知道這是給 CC 看的「到職須知」，改它等於改 CC 的行為 | 新人入職手冊 |
| `.claude/` 資料夾 | 知道 CC 的設定放這裡，別手動刪 | 辦公室的規章櫃 |

## 二、雲端與部署（Cloudflare）

| 詞 | 懂到什麼程度 | 店裡的比喻 |
|---|---|---|
| Cloudflare（CF） | 知道你的儀表板網頁、Telegram 的後台和五位工讀生都放在這個帳號下 | 租來的機房＋店面 |
| Worker | 知道它是一小段「有人來就回應」的程式，有自己的網址 | **櫃台**：有人敲門就辦事 |
| 部署 | 知道意思是「把改好的版本放上去讓大家看到」 | 新版公告貼出去 |
| wrangler | 知道它是 CC 用來操作 Cloudflare 的工具；它靠你設在環境裡的金鑰與 Account ID 登入，不會跳出瀏覽器 | CC 的出差公文包 |
| API 金鑰（token） | 知道是你授權 CC 動你 Cloudflare 的那把鑰匙，權限只開需要的 | 一張只開得了幾道門的門禁卡 |
| binding | 看到錯誤訊息提到它，意思是「櫃台和資料櫃之間的線沒接好」 | 櫃台後面少一條電話線 |

## 三、資料

| 詞 | 懂到什麼程度 | 店裡的比喻 |
|---|---|---|
| D1 | 知道訂單、排班、設備、工作日誌都存在這裡 | **資料櫃**（店的訂單資料櫃） |
| CSV | 知道是試算表另存的純文字檔，用來一次匯入資料；舊訂單系統就是匯出成它 | 一疊要建檔的紙本單據 |
| API | 知道是頁面和資料櫃之間的「窗口」，網址固定、格式固定 | 櫃台的服務窗口 |
| 合約（API 合約） | 知道前端已經照它寫好，後端要照做，不改前端 | 雙方簽好的介面規格 |
| Arcrun RAG | 知道它是店的知識庫；CC 動手前會先查它（不是靠關鍵字猜，是「地圖→目錄→整張卡」一路讀） | **資料室**＋阿珠姨的老鳥筆記 |

## 四、AI 與籠子（harness）

| 詞 | 懂到什麼程度 | 店裡的比喻 |
|---|---|---|
| 大模型（CC） | 知道全店一位、負責蓋工作流、值守和修正 | **AI 主管** |
| 小模型（Workers AI） | 知道它便宜、跑得快，但會出錯，所以每個工位都要用「籠子」圈住 | **工讀生**，指令要清楚 |
| 工位 | 知道本店有五個：門市客服、接單員、廚房排產、內勤小幫手、老闆日報；每個工位一位工讀生，只拿它需要的工具 | 店裡的五個崗位 |
| harness（籠子） | 知道是管住 AI 的那一套：給它什麼資料、准它做什麼、怎麼驗；不是 AI 本身 | 到職須知＋SOP＋門禁＋驗收單 |
| 工具 | 知道是工位「能做的事」，沒有的工具它就做不到（所以刪除、核准、改價根本不給） | 發給工讀生的鑰匙，不發就開不了 |
| 申請與核准 | 知道加急、取消、超額折扣、請假，工讀生只能「送出申請」，要店長在 Telegram 按核准才生效 | 工讀生遞單，店長蓋章 |
| Telegram bot / webhook | 知道客人、員工、店長都在 Telegram 上跟店溝通；webhook 是「有人傳訊息給 bot，Telegram 就敲你 Worker 的門」的那個網址 | 店門口的對講機＋傳話員 |
| 小模型挑工具 | 知道小模型的工作是「聽懂人話、從自己的工具菜單挑一個」，不是自己算價格、自己決定 | 工讀生翻 SOP 找對的那一頁 |
| MCP | 知道是讓 CC 接上別的系統（例如 Arcrun）的接頭 | 接線的插座 |
| skill | 知道是一份 CC 會照做的 SOP | 作業程序書 |
| hook | 知道是「做某件事之前自動先做另一件事」；本課的 hook 是部署前先跑測試 | **門口的檢查哨** |

## 五、測試、日誌與修正

| 詞 | 懂到什麼程度 | 店裡的比喻 |
|---|---|---|
| 驗收單（測試表） | 知道每題是「問什麼 → 應該看到什麼」，每個工位一組 | 出貨前的檢查表 |
| 一天的劇本 | 知道是一串從早到晚的事件（打卡、客人來問、下單、加急、報修、請假……），五個工位照順序跑一遍 | 老闆的驗收：把一天演一遍 |
| 綠燈／紅燈 | 綠＝過，紅＝沒過；紅燈不部署 | 紅綠燈 |
| 陷阱題 | 知道是故意出的「沒有的資料／超出權限／該擋沒擋」，通過的意思是**被擋下來** | 新人考核的刁難題 |
| 工作日誌 | 知道每個工位每個動作（包含被擋下的）都要記一筆；出錯時靠它找原因，老闆日報也從它長出來 | 每個崗位的值班日誌 |
| 轉正四條 | 答得對、擋得住、查得到、修得好；四條都過，工讀生才算轉正上班 | 試用期考核四項 |
| 閉環 | 知道管理制度是一個圈：修改 → 測試 → 核准 → 部署 → 調用，轉一圈就更穩一點 | 店的 PDCA |
| log（紅燈記錄） | 知道紅燈的細節會存在 `course/logs/`，丟給 CC 就能診斷 | 異常報告單 |
| SDD | 知道是「這個功能要做成什麼樣」的規格書，CC 改之前會先讀 | 工作指示單 |
