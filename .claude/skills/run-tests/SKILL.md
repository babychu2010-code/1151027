# run-tests：驗收單＋一天的劇本

這門課的東西都在 repo 的 `course/` 底下（根目錄只放 Claude 的 harness）；下面的 `tests/`、`scenario/`、`logs/`、`orders/`、`.ax303-gate` 都是指 `course/` 裡的那一份。烘焙坊的 Worker 專案根目錄也是 `course/`（`wrangler` 指令在 `course/` 裡跑）。

驗收單與劇本就是老闆的驗收：每一題寫「問什麼 → 應該看到什麼」。你的工作是**照表逐題問、照實對照**，不要幫工位說話。

## 第一次用：開部署閘

`course/` 底下沒有 `.ax303-gate` 檔就建一個（`course/.ax303-gate`），內容寫**已經蓋好的工位**，逗號分隔（例：`service`；五個都蓋好後是 `service,intake,kitchen,desk,report`）。有了它，專案的 hook 會在每次 `wrangler deploy` 前自動跑那些工位的驗收單，紅燈就不部署；五個工位都在時還會跑一天的劇本。每蓋好一個新工位，就把它加進這個檔。告訴學員一句：「已開啟『部署前必須測試通過』。」

## 怎麼跑

1. 確認後端在跑：在 `course/` 裡起本機 `wrangler dev`（預設 http://localhost:8787）。沒起來就在背景起一個（`cd course && npx wrangler dev`）。
2. 跑：`node .claude/scripts/run-tests.mjs --dir course`（在 repo 根目錄給 `--dir .` 也行，腳本會自己找到 `course/`）
   - 要測已部署的版本時加 `--base https://學員的網址`。
   - 只跑驗收單加 `--only tests`；只跑劇本加 `--only scenario`；只驗蓋好的工位加 `--stations service,intake`（`.ax303-gate` 就是這個清單）。
   - 跑之前與每個「會改資料」的題目前後，腳本會自動呼叫 `POST /api/reset`，把店的資料換回起始狀態（避免上一輪改過的資料讓題目變紅）。要略過加 `--no-reset`。後端若還沒做 `/api/reset`，請照 `orders/API-contract.md` 補上。
3. 把輸出的三張表原樣給學員看：驗收單、一天的劇本、**轉正四條**（五個工位 × 答得對／擋得住／查得到／修得好）。
4. 有紅燈：打開 `logs/` 最新一份 `red-*.md`，用白話告訴學員「哪個工位、哪一題、它回了什麼、哪裡不對」。

工位還沒蓋好時，那一組題會是紅燈（伺服器回 404），這是正常的：它代表「這位工讀生還沒上班」。學員說「試跑一天的劇本」就不加 `--stations`，讓它從頭跑到尾、看到哪裡還沒通。

## 驗收單格式（tests/<工位>/T01.md、X01.md）

```
# T01 客製蛋糕報價
- 問：我想訂 8 吋芒果蛋糕、進階造型，多少錢？
- 身分：（內勤、接單這類要知道是誰在說話時才填，例如 阿德）
- 應含：1,480
- 不可含：
- 會改資料：是（這題會改到店裡的資料時才加這一行）
```

`應含` 每一項都要出現、`不可含` 每一項都不能出現（用逗號分隔；同一項裡用 `|` 表示幾種說法任一種都算，例如 `不能|不可以|無法`）。T 開頭是一般題（答得對）；X 開頭是陷阱題（擋得住：沒有的資料／超出權限／該擋沒擋）。

## 劇本格式（scenario/one-day-script.md）

每個 `## 步驟N 標題` 是一件事，照順序跑，狀態會累積。有「工位／問／應含／不可含」的是問某個工位；「店長：核准 加急 LEO-2610-011」是人按核准（腳本去按訂單頁那顆按鈕）；「類型：陷阱」的步驟，通過的意思是被擋下來。

## 轉正四條怎麼看

| 條 | 意思 | 哪裡驗 |
|---|---|---|
| 答得對 | 一般題與劇本的回答，跟店的規則、訂單資料一致 | T 題＋劇本一般步驟 |
| 擋得住 | 陷阱題與陷阱步驟：該擋的有擋 | X 題＋劇本陷阱步驟 |
| 查得到 | 每個工位每個動作都在 `/api/logs` 留了日誌 | 跑完劇本後數日誌 |
| 修得好 | 紅燈修過、重跑後全綠 | `logs/` 有紅燈記錄、現在全綠 |

## 紅燈怎麼修（先問自己三格哪一格壞了）

1. 它沒拿到該有的資料 → 資料來源（D1 或 Arcrun RAG）沒接對
2. 它做了不該做的動作 → 該由程式擋，不是叫它「小心一點」；檢查那個工位是不是拿到了不該有的工具
3. 它的答案沒辦法驗 → 補測試題

修完**重跑整張表與劇本**，全綠才算好。修之前先查 Arcrun（規則、規格、歷史紀錄）。

## 不要做

- 不要為了讓測試變綠而改測試題或劇本。考題不對要先告訴學員，由學員決定。
- 不要跳過紅燈直接部署。
